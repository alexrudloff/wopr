## Overhead

wopr talks to a local mock model that answers every request with one fixed reply over OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages, so the model adds no time or variance. What remains is wopr: process startup, request construction, streaming, Session I/O, and teardown. These numbers say nothing about model quality.

`0.2.0`, measured 2026-09-27T13:37:11Z on darwin/arm64 (18 CPUs, go1.27.1). Each scenario ran 1 warm-up and 10 measured runs. Prompt: `Say hello`.

| Scenario | Median | p90 | CPU | Peak RSS | Requests | First request | System prompt | Tools |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Startup (--version) | 16.7 ms | 18.7 ms | 19.2 ms | 30.3 MiB |  |  |  |  |
| One prompt, streamed reply (OpenAI Chat Completions) | 24.0 ms | 36.7 ms | 32.1 ms | 39.6 MiB | 1 | 8,277 B | 3,609 B | 6 |
| One prompt, streamed reply (OpenAI Responses) | 26.1 ms | 31.1 ms | 32.6 ms | 39.1 MiB | 1 | 8,216 B | 3,609 B | 6 |
| One prompt, streamed reply (Anthropic Messages) | 32.8 ms | 35.3 ms | 31.0 ms | 38.9 MiB | 1 | 8,329 B | 3,609 B | 6 |

Peak RSS is the largest single process in wopr's process tree. Request sizes are HTTP request body bytes.

## Live tasks

A run passes when the task's check succeeds, no protected file changed, and wopr did not time out. Pass rate's ± is the standard error across runs.

## Reproduce

```bash
make evals                                   # overhead against the mock model
make evals-live MODE=auto,speed,quality      # live tasks, one row per routing mode
make evals-publish                           # regenerate this page
```

Results depend on the machine. Compare numbers from one run on one machine only.
