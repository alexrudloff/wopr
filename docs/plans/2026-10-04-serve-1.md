## 2. Supervisor surface (`coding/host/host.go`)

```go
// Host owns every session a served process runs.
type Host struct { /* unexported: svcs, sink, bus, registry mutex, map */ }

// New returns a Host over svcs. sink, when non-nil, also receives every published
// event's bytes: the single-consumer path, named by the item
// (/home/kc/dev/wopr/BACKLOG.md:39-40). Nil in slice 1; serve-2's rpc writer is
// the first real sink.
func New(svcs *coding.Services, sink func(Event, []byte)) *Host

// StartOptions is what a caller outside coding/host may configure. The model is
// a "provider/model" spec because the host resolves it: no caller here can import
// coding to build an *ai.Model itself.
type StartOptions struct {
	Model string // required, "provider/model"
}

// Start creates one session and registers it under its id. A duplicate id
// closes the new session and returns an error.
func (h *Host) Start(opts StartOptions) (*Session, error)

// Get returns a registered session. Second caller: the gate test starts session B
// through the registry and prompts it, proving the rejection is per session.
func (h *Host) Get(id string) (*Session, bool)

// Session is one session the host owns. It does not embed *coding.Session: an
// exported field would let a caller reach Send and bypass the run rule below.
type Session struct { /* unexported: host, id, sess, run sync.Mutex */ }

func (s *Session) ID() string
func (s *Session) Prompt(ctx context.Context, text string) error // ErrSessionBusy
func (s *Session) Close() error                                    // deregisters, then closes
```

`Start` resolves `opts.Model` through `coding.BuildModel(spec, h.svcs)`
(`coding/model.go:32`) and passes the result as `SessionStartOptions.Model` to
`coding.StartSession(h.svcs, opts)` (`coding/runtime.go:66`). It registers under
`Session.ID()`, which reads the session header's id (`coding/session.go:792` →
`internal/codingagent/session.go:398`).

`StartOptions` is one field on purpose. `coding.SessionStartOptions` has fourteen, every
one of them a `coding`/`ai` type (`coding/runtime.go:10-62`), so naming it would force the
cycle. Growing a host-owned struct is additive; changing a signature to thread one more
field through is a rewrite. Add fields when the first endpoint needs them.

`Close` deregisters before closing, so a closed session cannot be fetched from the registry
and the map does not accumulate dead entries. It closes via `Session.Close()`
(`coding/session.go:933`).

### The one-run-at-a-time rule

**Mechanism: one `sync.Mutex` field per `Session`, taken with `TryLock`.**

```go
// ErrSessionBusy reports that the session already has a run in flight.
var ErrSessionBusy = errors.New("host: session already has a run in flight")

func (s *Session) Prompt(ctx context.Context, text string) error {
	if !s.run.TryLock() {
		return ErrSessionBusy
	}
	defer s.run.Unlock()
	_, err := s.sess.Send(ctx, text)
	return err
}
```

**Enforced in `Session.Prompt`, before `Send` is entered.** One mutex. No global mutex, no
per-session flag, no channel semaphore, no lock hierarchy. It has to be enforced here
because it is the only layer above `coding`: `Session.mu` is declared `// serialises Send`
(`coding/session.go:117`) and held for the whole agent run (`coding/session.go:653`,
`:667-684`), so a second concurrent `Send` **blocks** rather than being rejected — the wrong
answer for a socket that must answer. The three primitives the backlog bars are `runGen`,
`InteractiveMode`'s TUI-only field (`internal/codingagent/interactive.go:97`), and the two
`queueMu`s in unrelated packages (`coding/session.go:180`,
`internal/codingagent/interactive.go:94`) (`/home/kc/dev/wopr/BACKLOG.md:24-26`, reasoned at
plan:261-265). `IsStreaming()` (`coding/session_run_state.go:25`) is ruled out on this
spec's own evidence, not the backlog's: it is a bare `atomic.Bool.Load()`, so checking it and
then sending is check-then-act and two callers can both read `false`.

Different sessions run concurrently because each `Session` owns its own mutex and the
registry lock is released before `Prompt` runs. **Lock-ordering invariant, and the reason it
is a comment rather than an obvious truth:** the registry `sync.RWMutex` and the bus mutex
are never held across `Send`, and the bus mutex is never held across a send on a subscriber
channel. Holding the bus lock while a subscriber channel send blocks would deadlock against
that subscriber's own `Close`, which needs the bus lock.

## 3. Event bus surface (`coding/host/bus.go`)

```go
// Event is one typed bus event. Publish marshals Data exactly once and hands
// the same bytes to the sink and to every subscriber.
type Event struct {
	Type    string // host event type; serve maps it to an opencode SSE name
	Session string // owning session id; "" for server-wide
	Data    any
}

// Bus is the typed event bus. Exported despite having no in-slice caller: the repo's
// `unused` linter rejects unexported dead code and the item names the bus. Unexporting
// this breaks gate 3.
type Bus struct { /* unexported: sink, mutex, subscribers */ }

func (b *Bus) Publish(ev Event)
func (b *Bus) Subscribe(buffer int) *Subscription

// Subscription is one subscriber's handle. doneCh is the field, Done the accessor:
// distinct names, so the select in Publish cannot be confused with the method.
type Subscription struct { /* unexported: bus, ch chan []byte, doneCh chan struct{} */ }

func (s *Subscription) Payloads() <-chan []byte
func (s *Subscription) Done() <-chan struct{}
func (s *Subscription) Close()
```

**Construction path.** `Host.New` builds the `Bus` with its sink. No exported `NewBus` and
no accessor, because nothing outside `coding/host` has a subscriber yet; serve-4 adds the
accessor when `/global/event` becomes the second real caller.

**`buffer` is a parameter, not a constant, and slice 1 picks no number.** The capacity
derives from a maximum event size, which is a property of serve-4's SSE mapping and does not
exist yet; any constant would be a guess recorded as a decision.

**Serialize once, share the bytes.** `Publish` calls `json.Marshal(ev)` once and passes the
resulting `[]byte` to the sink and to every subscriber, so fan-out is one pointer copy each,
never a per-subscriber marshal — plan:105-107 and :244. Nothing mutates a payload after
`Publish`.

**Unsubscribe leaks no goroutine and cannot panic.** `Close` removes the subscription from
the subscriber map under the bus mutex and closes `doneCh`. It does **not** close the payload
channel. `Publish` snapshots the subscriber list under the mutex, then sends outside it:

```go
select {
case sub.ch <- payload:
case <-sub.doneCh:
}
```

Closing the payload channel would be the shorter code and it is wrong twice: a `Publish`
already past the mutex would send on a closed channel, and holding the mutex across the send
to avoid that deadlocks against a consumer that calls `Close` when the channel is full.
`doneCh`/`Done` is the correct termination signal, and every consumer selects on it.

**Reuse path for serve-4, recorded so it does not build a second mechanism.**
`Session.Subscribe(listener func(agent.AgentEvent)) func()`
(`coding/session.go:1648`) already delivers a session's typed events to a listener that
returns its own unsubscribe func. serve-4 should feed SSE from that plus one
`json.Marshal` in the handler — or from this bus, once a serve-4 handler subscribes — not
from a third path. `Session.Events()` (`coding/session.go:769`) is the channel a subscriber must
drain for `Send` to finish, so it is a pump to keep alive, not a consumer surface.

**Not in this slice:** the bounded per-connection buffer sized in bytes, and the terminal
drop event. The plan puts both in serve-4 (plan:238-243,
`/home/kc/dev/wopr/BACKLOG.md:89-104`), and they need the maximum event size this section
just declined to guess at. Slice 1's `Publish` blocks on the subscriber channel, which
cannot bite because slice 1 has no subscriber in production. **serve-4 replaces that send
with a byte-derived bound and a non-blocking send plus the terminal drop event.**

Also not in this slice: a bus test. `AGENTS.md` asks for one small behavioral test only
where a regression costs money, loses data, or weakens safety; a subscriber leak is first
observable in serve-4's fan-out test, which the plan already requires.



**Flag parsing follows the repo's value-flag precedent at `cmd/wopr/args.go:169-178`**:
`for i := 0; i < len(args); i++` with a `stringFlags`-shaped map and `i++; *p = args[i]`.
Not `cmd/wopr/config_command.go:22-38`, whose all-boolean switches cannot read a value.
Space-separated only, no `--flag=value`, because no flag in this CLI has one.

That precedent has no empty-value check, so this command adds one **in the loop, before the
assignment** — the only place a missing or empty value is still detectable without extra
state:

```go
if p, ok := stringFlags[arg]; ok {
	if i+1 >= len(args) || args[i+1] == "" {
		fmt.Fprintf(os.Stderr, "wopr serve: %s requires a non-empty value\n", arg)
		return 2
	}
	i++
	*p = args[i]
	continue
}
```

Without it `--hostname ""` is indistinguishable from an absent flag, the override below never
fires, and the command silently binds `127.0.0.1`. All-interfaces is spelled `0.0.0.0`.

**Exit-code convention, matching the repo's split:**

- Usage error (unknown flag, non-integer or non-positive `--port`, a value flag with a
  missing or empty value): print the usage line to stderr and `return 2` — the `default:`
  branch shape at `cmd/wopr/status_command.go:73-75` and `cmd/wopr/auth_commands.go:72-74`.
- Runtime failure (`os.Getwd`, trust-store read, bind failure): `failf(...)`, which
  **returns 1** (`cmd/wopr/profiling.go:28-31`). Do not assume 2 from `failf`.
- `-h`/`--help` prints usage and returns **0**. It is its own case, explicitly excluded from
  the `default:` branch above (`cmd/wopr/status_command.go:70-72`,
  `cmd/wopr/update_command.go:33-35`).

**Precedence: flag, then settings, then default.**

```go

if flagPort != 0 { port = flagPort }
host := settings.GetServerHostname()      // 127.0.0.1
if flagHost != "" { host = flagHost }
```

### Non-loopback exposure warning

The plan gates the warning on the bind address, not on first run
(plan:229-230): loopback is the default bind, and a non-loopback bind prints the exposure
warning. To stderr, before `srv.Serve(ln)`, with no state carried between runs:

```
wopr serve: no authentication. Anyone who can reach <addr> can run tools and
read files as this user. Binding to a LAN is not a security control.
```

Trigger condition — warn unless the host is a loopback literal. There is no empty-host
branch, because `host` is never empty: the parse loop rejects an empty flag value, and
`GetServerHostname` maps `""` to `127.0.0.1`. All-interfaces is spelled `0.0.0.0`, which is
not loopback and therefore warns.

```go
func nonLoopbackBind(host string) bool {
	if host == "localhost" {
		return false
	}
	ip := net.ParseIP(host)
	return ip == nil || !ip.IsLoopback()
}
```

`net.ParseIP` returning nil for a hostname means it is not a loopback literal, so it warns
— the conservative direction. One unexported function in `serve.go`, one caller; not a
package. Note the honest asymmetry: a firewalled LAN
interface still warns, because the warning is about reachability, not about whether a packet
will actually arrive.

### (a) `coding/host/host_test.go` — `TestHostRejectsASecondConcurrentPromptPerSession`

- **Assertion.** With a prompt in flight on session A, `A.Prompt(ctx, "second")` returns
  `ErrSessionBusy`, checked with `errors.Is`. Meanwhile `B.Prompt(ctx, ...)` for a different
  session is accepted and its request reaches the provider. Both halves matter: the first
  proves the rule exists, the second proves it is per session rather than a global lock.
- **No clock, and that is the point.** The provider has not answered, so the first run is
  provably still in flight; the second prompt returning at all *is* the non-blocking proof.
  Do not assert on elapsed time — a timing assertion is the flaky way to say this.
- **Hermetic setup.** A `TestMain` in the same file (one test file in this package, so no
  separate `testmain_test.go`) mirroring `coding/testmain_test.go:15-49`: unset
  `WOPR_CODING_AGENT_DIR` and `WOPR_CODING_AGENT_SESSION_DIR` (`:21-27`); unset every key
  from `ai.ProviderCredentialEnvVars()` **and** `web.SearchEnvVars()` (`:30`); apply
  `aitest.HermeticCredentialEnv(testRoot)` (`:33`) so no cloud SDK chain reaches instance
  metadata; point `WOPR_HOME` at a temp dir removed afterwards (`:36-40`). `t.Setenv` cannot
  unset, so this is a `TestMain` and not an in-test loop.
- **The blocking provider — no fake model provider needed.** Use `httptest.NewServer` on
  loopback with a handler that signals a buffered channel on entry and then blocks until the
  test closes a release channel. Write a `models.json` under the temp `agentDir` whose
  `anthropic` entry sets `baseUrl` to that server's URL and `apiKey` to `"test-key"`, then
  build the model by spec. This is the shape of `coding/session_cache_warming_wire_test.go:30-50`
  (handler), `:64` (`httptest.NewServer`), `:68` (`WOPR_HOME` temp), `:75` (`models.json` with
  a loopback `baseUrl`), `:81` (`NewServices`), `:85` (`BuildModel`). Real Anthropic provider
  code, loopback socket, no credential, nothing off-host.
- **Why not `WOPR_TEST_FAUX`.** `ai.TestFauxProvider` (`ai/test_faux.go:95`) needs no HTTP and
  is reachable via `coding/model.go:161-166`, which is cheaper still. It is the wrong tool:
  the only scenario that blocks is `"Run: sleep for a while"` (`ai/test_faux.go:322-327`),
  which spawns a real `sleep 45` subprocess. Every other scenario returns immediately, so
  "is a run in flight?" becomes a race and the test becomes flaky.
- **Release before the test ends**, and the second session's prompt too, or `go test` hangs:
  `defer close(release)` plus `defer` close on both sessions.
- Run this package under `-race` (gate 5 above). A concurrency assertion without `-race` is
  a weak gate.

### (b) `internal/codingagent/serve/serve_test.go` — `TestHealthAnswersOverARealListener`

- **One shape, decided.** `New` binds, so the test calls `New("127.0.0.1:0")` exactly once
  and drives the request over the listener it returns:

```go
srv, ln, err := serve.New("127.0.0.1:0")
if err != nil {
	t.Fatal(err)
}
go func() { _ = srv.Serve(ln) }()
t.Cleanup(func() { _ = srv.Close() })
resp, err := http.Get("http://" + ln.Addr().String() + "/global/health")
```

  Never bind a listener in the test and then hand the same address to `New`: that is a
  guaranteed `EADDRINUSE`. Never use `httptest.NewRequest` against the `*http.ServeMux`
  either — it bypasses the `http.Server` and the socket, and the gate says "over a real
  listener".
- **Assertion.** Status `200`; `Content-Type` beginning `application/json`; body decoding to
  `{"healthy":true,"version":version.Version}`. All three, not just the status: a 200 with
  the wrong body is the failure the client's Test connection would report as working.
- **Hermetic.** No credentials, no `WOPR_HOME`, no provider: the handler reads one constant.
  Nothing to make hermetic beyond the loopback interface. Do not import `ai` here.
- Not a table. One request, one assertion set — a table over paths would be the
  exhaustive-table shape `AGENTS.md` forbids.
