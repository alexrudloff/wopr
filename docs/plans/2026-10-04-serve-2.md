## 2. The two structs

```go
// RPCOptions is what a caller supplies to ServeRPC. Every field is required.
type RPCOptions struct {
	// In is the JSONL command stream. The engine never names a stream of its
	// own, so one process can drive one session per call from any reader.
	In io.Reader
	// Write is the engine's single write seam: every response and event goes
	// through it. Nil panics on the first write.
	Write func(any)
	// Cmds is the command catalog. The engine cannot build these itself — the
	// catalog's wire shapes are protocol types assembled in package main, which
	// this package cannot name.
	Cmds RPCCommands
	// CWD and SessionDir locate the session transcript directory; NoSession is
	// the CLI's --no-session.
	CWD        string
	SessionDir string
	NoSession  bool
}

// RPCCommands is the catalog dependency ServeRPC calls.
type RPCCommands struct {
	// Commands returns the get_commands list, whose shape the catalog owns.
	Commands func() []RPCSlashCommand
	// Resolve returns the built-in command a message invokes, if any.
	Resolve func(message string) (name, args string, ok bool)
	// Expand substitutes a skill or prompt-template invocation.
	Expand func(message string) string
	// Run executes a resolved built-in command. Its bool return is dropped:
	// the command's own output is the response, and there is none to send.
	Run func(ctx context.Context, name, args string)
	// Export writes an HTML export of a session transcript and returns its path.
	Export func(sessionPath, outputPath string) (string, error)
}
```

Six plus five, all required. A plain struct of funcs, not an interface: the repo already passes
writers and listeners this way — `rpcNotifier(output func(any))` (`cmd/wopr/rpc_notify.go:12`),
`rpcCommandCatalog.notify` (`cmd/wopr/rpc_mode.go:44`), `Session.Subscribe(listener
func(agent.AgentEvent)) func()` (`coding/session.go:1648`) — and `.golangci.yml:21-25` enables
`iface`, which rejects opaque single-implementation interfaces. The named fields are also
independently replaceable, which matters because `cmd/wopr` assembles them from method values
plus one closure. `Export`'s signature matches `export.ExportFromFile(inputPath, outputPath
string) (string, error)` (`internal/codingagent/export/export.go:186`) exactly, so it is a bare
method value, and `cmd/wopr` already imports that package at `cmd/wopr/main.go:25`.

**Zero-value contract.** All eleven fields are required; `cmd/wopr` is the only caller and sets
every one. No runtime check. A nil `Cmds.Commands` would panic inside the dispatch loop, and
`TestRPCContract` would not catch it because that test never sends `get_commands`; and since
`ServeRPC` returns an exit code rather than an error, a failed check would present as a silent
startup failure. If a second caller appears, that caller is where the check belongs.

## 4. The write seam

### 4.1 One writer, built in `cmd/wopr`, retained byte-identical

`cmd/wopr/rpc_mode.go:167-172` does not change:

```go
// writeMu serializes every write to the RPC stream. Responses and events share one
// stream, so an unsynchronized write would interleave two JSONL records.
var writeMu sync.Mutex
writeRPC := func(v any) {
	writeMu.Lock()
	defer writeMu.Unlock()
	writeJSONLine(os.Stdout, v)
}
```

It is built in `runRPCMode` and handed to `ServeRPC` through `opts.Write` and to `rpcNotifier`
through the catalog's `notify`. **The backlog's "delete the `os.Stdout` closure"
(`/home/kc/dev/wopr/BACKLOG.md:93-94`) is read as: the engine must name no writer.** The closure
cannot be deleted outright — something has to own stdout, and `writeJSONLine`
(`cmd/wopr/rpc_types.go:446`) must stay for `print_mode.go:176,200`, so it does not move either.
Moving it would cost two more edits in `print_mode.go` and put a stdout-ownership choice on the
server's dependency path.

### 4.2 The bus is not the write path

`Bus.Publish` marshals with `json.Marshal` (`coding/host/bus.go:44`), which HTML-escapes `<`,
`>`, and `&`. The RPC writer uses `json.NewEncoder` with `SetEscapeHTML(false)`
(`cmd/wopr/rpc_types.go:449`), and the comment above that function (`:443-445`) states the rule:
never `json.Marshal` for strings that reach display or wire output containing shell operators.
Routing RPC through the bus would put `&&` on the wire as `\u0026\u0026` — a silent wire change
that `TestRPCContract` cannot catch, because its transcript (`cmd/wopr/rpc_mode_test.go:201`)
contains no shell operators.

`host.New`'s `sink` therefore stays nil and `coding/host/host.go:21-24` is corrected to stop
promising otherwise. The `Export` injection is a minimal-code decision, not a dependency win:
`coding/host` already reaches `tui` transitively through `coding`, so `opts.Cmds.Export` removes
one needless edge (`export.go:15`) and adds nothing.

## 5. Per-session state, and three things a rewrite would break

The backlog calls four things process-scoped (`/home/kc/dev/wopr/BACKLOG.md:99-101`). They stop
being process-scoped because each `ServeRPC` call builds its own, not because a struct owns them.
That is the whole of the claim, and the wait-group grep in the DoD is how you check it.

What changes is the lifetime, not the shape. A served process holding several sessions calls
`ServeRPC` once per session, so each call has its own wait groups, its own `settlePrompt`, its
own `streaming()`, and its own cancellation; nothing is shared. That, plus the wait-group grep in
the DoD, is the whole of the backlog's promise
(`/home/kc/dev/wopr/BACKLOG.md:99-101`). Three things the verbatim move preserves that any
rewrite would not:

- **`context.Background()` at `:245`**, inside `settlePrompt`. `WaitForIdle(context.Background())`
  must outlive `abort`'s cancellation; it is what makes an in-flight run stop before the caller
  answers. Any rewrite of `ctx` in this file is a bug. The DoD greps for it.
- **The untracked goroutine at `:316-319`** — a bare `go func` with no `WaitGroup`, so
  `settleSessionWork()` cannot wait for it. It is not `commandWG`-spawned, and `compact` spawns
  its own at `:508-516`.
- **`currentSession := sess` at `:485` and `:507`.** These snapshot the session for a
  `commandWG.Go` closure. They are not redundant — `ReplaceInner` (`coding/session.go:901-931`)
  changes the inner transcript, and a reader who "simplifies" them is guessing.

1. **`rpcCommandCatalog` accidentally moves.** The largest risk, because it looks like engine
   code. It is not: it builds `[]RPCSlashCommand` (`cmd/wopr/rpc_mode.go:53,72`) and
   `cmd/wopr/llama_test.go:23` names the type. If it moves, the build breaks in a test file and
   the fix is a test edit, which is the forbidden outcome.
2. **A wire change slips in through the encoder or a key.** `SetEscapeHTML(false)`
   (`cmd/wopr/rpc_types.go:449`) must survive, §4.2 rules out the bus, and every JSON tag is one
   field rename from a wire change — `RPCModel` (`rpc_types.go:176-193`), `RPCSessionState`
   (`:196-209`), `RPCBashResult` (`:291-297`), the `map[string]any` DTOs at `rpc_mode.go:850-868`,
   and every literal key in `rpc_events.go`. `TestRPCContract` will not catch an escaping change.
   Check by reading.
3. **Teardown order is uncovered.** `coding.Session.Close` is called twice today — from the
   `defer` at `cmd/wopr/rpc_mode.go:183` and explicitly at `:839` — and order is preserved because
   the `defer` is registered first. **Idempotency is not claimed**: `coding.Session.Close`
   (`coding/session.go:933`) guards only `close(s.closeDone)` with `sync.Once`, and
   `interruptTasks`, `AbortRetry`, `AbortBash`, `AbortCompaction`, `AbortBranchSummary`,
   `closeCacheWarming`, `closeMCP`, and `s.learner().Close()` all re-run on the second call.
   Pre-existing. `TestRPCContract:201-202` does **not** cover this: it awaits `agent_settled` and
   nothing else, and `await` discards every non-matching record, so no ordering assertion exists
   anywhere. Mitigation is the verbatim copy plus `-race`.
4. **An unexported `package main` helper is orphaned.** The measured `unused` rule under this
   repo's config: a zero-caller **unexported** symbol in `package main` **is** flagged; a
   zero-caller **exported** symbol in `package main` is **not**; exported symbols in
   `coding/host` are **not** flagged. So this slice's ~35 new exported DTOs carry no lint risk at
   all, and the live hazard is exactly one thing: a symbol in `cmd/wopr` that loses its last RPC
   caller. Dropping the `:177` call orphans two at once — `refreshCatalogsInBackground` and
   `catalogRefreshTimeout` (`cmd/wopr/llama.go:18,32`). §5's keep-list is the checklist;
   `refreshCatalogsInBackground`, `newSessionManagerWithDir`, `isWithin`, and `failf` are the four
   that would trip it.
5. **The lint gate is cached.** `go tool golangci-lint cache clean` first, or a stale pass can
   print `0 issues` while warning about a deleted sibling worktree.

## 7. Notes for the implementer

- **STOP-AND-REPORT** if any step turns out to need an edit to a `*_test.go` in `cmd/wopr` or
  `coding/host`. §3.2 names the only symbols that could force it. An edit to
  `cmd/wopr/llama_test.go` in particular means someone decided to move `rpcCommandCatalog`,
  which means the wire-ownership argument in §3.2 was bypassed.
- The moved region is a copy. Where §1.1 lists a rewrite, make that rewrite; anywhere else,
  including comments and blank lines, do not improve it. If the diff exceeds roughly 40 changed
  lines outside the moved block, something has been rewritten that should have been copied.
- Comments state current behaviour and non-obvious invariants, never plan narration. The three
  that must change are `coding/host/host.go:21-24` (§4.2), `cmd/wopr/rpc_types.go:27` (§3.5), and
  the forwarder comment at `cmd/wopr/rpc_mode.go:202` (§1.1). Do not hard-wrap prose or comments
  to a terminal width.
- Everything the move needs is stdlib; `go.mod` gains no dependency.
- Two traps in `coding/host` that this slice must not "fix", both standing constraints:
  `Bus`/`Subscription` are exported with no in-slice caller **on purpose**, because `unused`
